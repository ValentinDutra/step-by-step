# Add Codex & Gemini CLI support with per-phase model selection (#16)

## Goal
Let each pipeline phase run on a different LLM CLI (Claude, Codex, or Gemini) and a different model, selected via a TOML config file. Today every call goes through one hardcoded function (`app/claude.py::call_claude`) that shells out to the `claude` binary. We introduce a provider abstraction, a config layer keyed by phase name, and Codex/Gemini implementations. With no config present, behavior is identical to today (all Claude, with cost reporting).

## Approach
A `LLMProvider` Protocol with one async method (`run`) and three implementations (`ClaudeProvider`, `CodexProvider`, `GeminiProvider`), each a thin subprocess shell over a pure parsing function. The provider for each phase is resolved from config in `create_stages()` and attached to the `Stage`. This was chosen over a registry/if-else dispatch because it gives clean dependency injection (the provider is data on the `Stage`), matches the existing dataclass style in `app/models.py`/`app/stages.py`, and isolates the brittle per-CLI parsing into pure, unit-testable functions. Each provider records its own cost into the `pipeline_stats` singleton inside `run()` (mirroring what `app/claude.py` does today), so every call — stages, workers, decomposer, quality-gate — is counted without threading cost through every caller. Config is TOML read with stdlib `tomllib` (no new runtime deps), keyed by phase name so it is forward-compatible with #17 (configurable phases).

## Constraints
- Do NOT change pipeline behavior when no config file exists — all phases must default to Claude with cost reporting exactly as today.
- Do NOT add USD cost estimation from tokens for Codex/Gemini. Their `cost_usd` is `None`.
- Do NOT add per-provider custom binary paths or extra flags. Binaries are looked up on PATH by name (`claude`, `codex`, `gemini`).
- Do NOT add a provider override for the quality-gate (`evaluate_should_iterate`) or the decomposer beyond what `[defaults]` and the Decomposition phase config give.
- Do NOT manage CLI authentication. Each CLI handles its own auth; auth errors surface through `ProviderResult.error`.
- Do NOT add per-worker provider selection. Selection is per-phase only.
- Do NOT hardcode model name lists or validate model strings. Models are pass-through; the CLI rejects invalid ones.
- Do NOT record cost at the pipeline call sites — providers record their own cost. Recording in both places double-counts.
- Do NOT add a linter/type-checker or reformat untouched code. There is none configured today.

## Patterns to follow
- Dataclasses: follow `app/models.py` (`Task`, `WorkerResult`) — plain `@dataclass`, typed fields, defaults.
- Async subprocess + streaming + JSONL line parsing: follow `app/claude.py::call_claude` (lines 24-112) — `asyncio.create_subprocess_exec`, write prompt to stdin then close, concurrent stderr drain, buffered line splitting on `\n`, `asyncio.timeout`, cleanup in `finally`.
- Cost recording inside the provider: follow `app/claude.py:100-112` (`pipeline_stats.add_call(...)` then return).
- `on_stream` callback contract: a callable taking one `str` chunk; may be sync or async — replicate the `asyncio.iscoroutinefunction(on_stream)` handling at `app/claude.py:76-79`.
- Stage definition: follow `app/stages.py` (`Stage` dataclass and `STAGES`/`create_stages`).
- CLI arg parsing: follow `app/tui.py::main` (lines 161-183, `argparse`).

## Desired end state
- `app/providers/` package with `base.py` (`ProviderResult`, `LLMProvider` Protocol), `claude.py`, `codex.py`, `gemini.py`.
- `app/config.py` loads TOML and resolves a `{phase_name: (provider_instance, model)}` mapping with precedence `--config PATH` > `<repo>/step-by-step.toml` > `$XDG_CONFIG_HOME/step-by-step/config.toml` (default `~/.config/...`) > built-in all-Claude default.
- `Stage` carries `provider`, `provider_name`, `model`. `create_stages(resolved)` attaches the resolved provider per phase; both `app/runner.py:46` and `app/runner.py:360` pass the resolved mapping.
- `pipeline.py`, `workers.py`, `agents.py` use the injected provider; `app/claude.py` (old `call_claude`) is gone; `evaluate_should_iterate` lives in `app/evaluation.py` and uses the `[defaults]` provider.
- Each provider records its own cost via `pipeline_stats.add_call`; `add_call`/`format_cost` tolerate `None`, so a `None` cost never reaches a `:.4f` format.
- Invalid config (unknown provider or phase name) fails fast at load; missing provider binaries fail before phase 1 with install instructions.
- Running a config that sets, e.g., `[phases."Code Quality"] provider="codex"` makes the Code Quality phase shell out to `codex exec` while other phases stay on Claude. With no config, the pipeline runs all-Claude as before.
- Stats bar shows partial cost with `(+N n/a)` when non-Claude calls occurred.
- `uv run pytest` passes with ~6-9 deterministic tests.

## Edge cases and risks
- Gemini refuses to run headless in an untrusted directory ("Gemini CLI is not running in a trusted directory"). `GeminiProvider` MUST set `GEMINI_CLI_TRUST_WORKSPACE=true` in the subprocess env (or pass `--skip-trust`); the target repo is never pre-trusted. Verified against `gemini` 0.46.0.
- Gemini `--output-format json` returns one buffered JSON object (`{session_id, response, stats}`), not streaming JSONL — parse `.response`. It can be unreliable in some versions (google-gemini/gemini-cli#9009): on empty/malformed JSON, `GeminiProvider` must fall back to `--output-format text` and treat stdout as the output. Exercise both paths.
- Codex `--json` ignores `--output-schema` when MCP/tools are active (openai/codex#15451). We do NOT use `--output-schema`; we parse agent-message events. Not affected, but do not add output-schema.
- Prompt delivery under a non-TTY asyncio subprocess differs per CLI: Claude reads stdin, Codex uses the `-` PROMPT arg with stdin, Gemini headless triggers on `-p`/non-TTY. Verify at implementation time which form accepts piped stdin cleanly; record the working invocation in `learnings.txt`.
- Each CLI's JSONL event schema differs (field names, event types). Fixtures must be real recordings captured from each installed CLI (`codex` and `gemini` are installed locally), not hand-guessed shapes. If `GEMINI_API_KEY`/login is missing, the Gemini fixture cannot be recorded — note it in `learnings.txt` and do not fabricate it.
- `cost_usd: None` must never reach a `:.4f` format — that is the regression the cost task guards against; it is sequenced before the first provider that returns `None`.
- Removing `app/claude.py`: `evaluate_should_iterate` also lives there. Relocate it to `app/evaluation.py`, do not delete it.
- Streaming callback may be sync or async — preserve the `iscoroutinefunction` branch in every provider.
- Preflight uses `shutil.which`; only check providers actually referenced by the resolved config, not all three.
